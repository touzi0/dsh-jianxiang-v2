# dsh-transcript-fold —— 折叠时机模组（坚祥定制）

替换官方 `ui-chat` 行，只改**折叠时机**，折叠的样子（行、样式、按钮、「N 次工具调用」文案）完全沿用官方。

## 折叠规则

| 时机 | 行为 |
|---|---|
| 回合进行中，执行过程 ≤ 10 行 | **不折叠**（与官方一致） |
| 回合进行中，执行过程 > 10 行 | 只保留**最新 10 行**，更早的持续折叠（既看得见在跑什么，又方便往上翻） |
| 助手**中间正文**跨过阈值 | 该段正文保持可见，**它上方的思考与工具调用折叠**（优先于尾巴窗口） |
| 回合的**最终输出**出现 | **它上方全部折叠**（不等回合关闭） |

- 阈值取自旧折叠体系（`packages/client/ui-conversation/.../chat-flow.ts`）：**3 个非空行**，或 **85 个全角当量字符**（CJK/全角记 1、半角记 0.5）。
- 只统计**助手的中间正文**（`text` 块）；思考、工具结果不算。
- 尾巴窗口行数常量 `TAIL_ROWS = 10`（`patch/turn-process.ts`）：一行 = 一个 Assistant 步骤行或一次工具调用行；边界落在第 11 行上，所以"最新的 10 行"始终露着。
- **手动展开会保持**：你点开折叠条后，回合继续跑、锚点不断前移也不会再自动折回去；只有再点一次收起、或换到下一个回合，才回到折叠态。
- **不分新老对话**：只要该回合的节点在浏览器已加载的窗口里，够条件就折；老会话不再因为「还有更早分页没加载」而整体失效。

## 自动加载更早历史

`ChatView.tsx`（注入式补丁）：向上滚动时，只要"加载更早"按钮进入滚动容器顶部 **600px 的预加载带**，就自动拉上一页——按钮还没露面就已经在加载；**只要哨兵还在带里就一页接一页地拉**，一直往上滑就持续加载。

**锚点定在视口中下部（约 70% 高度那一行）**：拉页前记住那一行，新页落地后用 `scrollTop += flowTop(row) - hold.top` 把它钉回原坐标——新内容长在上方，你正在看的内容不动，所以"一边往上滑一边持续加载"既不会卡住、也能一路滑到最老。

- 官方原本钉的是**视口顶部第一行**：连续加载时补偿会不断抵消用户往上滑的动作，表现为"卡住 / 滑不到底"；本模组改用中下部锚点，并在拉页前清空 `anchorRef`，让官方那套顶部补偿让位。
- 预加载带宽度：`rootMargin: '600px 0px 0px 0px'`（写在 `build.mjs` 的 `INJECTIONS` 里）。
- 拿不到中下部锚点（空列表 / 布局未就绪）时退回官方 `loadOlderAnchored()`；浏览器不支持 `IntersectionObserver` 时退回手动按钮。

## 与官方 `ui-chat` 的差异（三处）

| 文件 | 改动 |
|---|---|
| `src/client/conversation-nodes/turn-process.ts` | ① 新增长中间正文锚点：按步骤累积正文、判阈值、把 `answerAnchorSeq`/`answerStep` 指到该步骤（该步骤没有工具调用时才算锚点）；② 新增执行中的尾巴窗口：按顺序记「步骤行 + 工具调用行」，没有锚点时把倒数第 `TAIL_ROWS` 行当边界 |
| `src/client/chat/ChatNodeSeat.tsx` | ① `processWindowReady` 不再要求 `processPresentation.turnClosed`（官方要等整回合收到 `turn/end` 才折，这就是「上方经常没折起来」的原因）；② 不再要求 `!historyIncomplete`（官方把「还有更早分页没加载」当成整个会话不能折的理由，长会话里连完整回合也不折）；③ 手动展开不再因锚点移动而失效：去掉 `storedEntry.answerStep === answerStep` 的比对，改成「本回合有记录就是展开」——否则执行中每来一行新事件就会被折回去 |
| `src/client/chat/ChatView.tsx`（**注入式**） | 顶部哨兵 + `IntersectionObserver`（rootMargin 600px）自动加载更早历史：按钮还没露面就预加载，哨兵在带内就持续拉页；`foldHoldRow` 把**视口中下部约 70% 处那一行**当锚点做补偿，官方顶部锚点补偿让位，因此能一边往上滑一边持续加载而不卡住 |

## 目录

```
package.json    模组清单：jx.replaces=["ui-chat"]，宿主 peerDependencies
index.js        宿主半边：补回被替换掉的 ui-chat 设置注册（transcriptView 是折叠总开关）
patch/          两处改动的完整文件（官方升级后对着新版本重新 diff）
build.mjs       构建：备份官方源码 → 落补丁（整份替换 + 定点注入）→ 官方 tsdown 重编 → 取产物改 id → 恢复官方树
lib/client.js   构建产物（浏览器半边，勿手改）
```

## 构建

```sh
cd 插件\dsh-transcript-fold
node build.mjs
```

- 用仓库自带的官方 tsdown 与官方 `packages/client/ui-chat/tsdown.config.ts` 构建，产物外部依赖只有平台基线（react / react-dom / client-store / ui-primitives）。
- 结束后官方源码与 `lib/` 产物**原样恢复**（可用 `git status -- packages/client/ui-chat` 验证为空）。
- 官方升级后重跑本脚本即可；若补丁锚点失效会**显式报错**（不会静默产出错包）。

## 启用与测试

1. 设置 → 插件 → 坚祥模组里确认 `dsh-transcript-fold` 已开（清单里 `jx.replaces` 会同时禁掉原生 `ui-chat`）。
2. 重启服务（`启动坚祥.bat`），并**刷新浏览器页面**（浏览器半边按模块缓存，重启不够）。
3. 看四个场景：
   - 回合跑到一半、执行过程 ≤10 行：上方**不该**折叠；
   - 执行过程超过 10 行：只留最新 10 行，更早的折起来；
   - 助手写出一段长中间正文（≥3 行或 ≥85 全角字）：这段保持可见，它上方折起来；
   - 最终回复出现：上方全部折起来，**不需要等回合结束**；
   - 往会话上方滚：**不用点**「加载更早」，接近顶部就自动续上更早的历史。
4. 若右侧或会话区异常，先关掉本模组开关再重启即可回退。

## 已知边界

- 官方 patch 不能改写原生行的模块名，所以本模组是「禁用 `ui-chat` + 插入自己的替代行」，产物 id 为 `dsh-transcript-fold`。
- 浏览器半边是官方工具链构建的**官方包副本**：官方 `ui-chat` 客户端以后若有新功能，需要重跑 `build.mjs`（patch 文件可能要跟着 diff）。
- 折叠总开关仍是官方设置 `ui-chat.transcriptView`（`compact` 才折叠）；本模组不改变该项的默认值。
- 放宽分页门槛的代价：分页窗口**顶端那个被截断的回合**，折叠条上的工具计数会少算没加载进来的部分（内容不会被藏起来，因为没加载的节点本来就不在页面上）。
- 排障：会话行的 DOM 上带 `data-turn-process-member` / `data-turn-process-hidden` / `data-turn-process-answer` 标记——有标记说明折叠判定生效了，没标记说明锚点或总开关没满足。
